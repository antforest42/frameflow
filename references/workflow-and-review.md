# 工作流与审核规则

## 一次完整运行

1. 接收标题和正文，在外层项目目录中建立唯一的 `项目文件/`。
2. 分离标题与正文；标题用于可选片头、封面、正文左上角页眉和计划，不进入显示字幕或朗读。
3. 合并误换行、恢复正文标点，写入 `normalized_script.txt`，不改写原文字词。
4. 按语义切分显示字幕，恢复内部标点并生成临时显示SRT。
5. 调用曼波 API 自动生成连续正文朗读；自然分段只服务于接口限制，不形成朗读间隔。
6. 加入第118帧片头静音，以真实朗读重算 `subtitles.srt` 和 `timeline.json`。
7. 此时视频总时长、每条字幕时间和每张图片可用的驻留区间已经确定。
8. 根据真实时间轴规划场景，优先复用已有批准图片；新图使用最多3张在途的连续滚动任务池。任务包完成后立即发出首批，任一张完成后先补发下一张，再把已完成原生图直接归一化写入项目并做单图初审，禁止固定批次屏障和尾部集中处理。
9. 全部项目图片就绪并完成必要整组审核后立即生成、交付统一交互审核页，详细测速报告和非阻塞诊断随后进行。正文左上角直接使用固定头像和 `plan.title` 中的本期主标题，不再规划副标题或账号文字。
10. 停止，等待用户确认正文 BGM、是否保留片头、片头文案与分行、横竖两套封面文案与布局和全部配图。
11. 只重做用户点名的图片，保留其余已通过内容。
12. 全部通过后生成 `approval.json`。
13. 验证正文覆盖、内部标点、真实音频、连续时间轴、图片覆盖、背景、配置和审批状态。
14. 生成横版4:3与竖版3:4两张封面和无声画面轨，再将朗读和审核页选定的固定音量背景音乐合成唯一最终成片。
15. 运行 `publish_project.py`，外层只发布标题命名的视频、两张封面和 `项目文件/`。
16. 运行 `scripts/check_skill.py` 做只读体检；它会在系统临时目录用独立 schema 2 固定项目重新生成审核页，并实际自动点击、拖动和断言。任何失败或提醒未解决前不得同步或固定正式 Skill。

## 审核是硬门槛

`approval-template.json` 只是待填写模板，不代表通过。最终渲染要求存在 `approval.json`，且至少满足：

```json
{
  "approved": true,
  "selected_bgm_id": "A",
  "include_intro": true,
  "intro_lines": ["用户确认的第一行", "用户确认的第二行"],
  "covers": {
    "landscape": {
      "title_lines": ["横版第一行", "横版第二行"],
      "accent_char_indices": [5, 6, 7],
      "text_center_x": 830,
      "first_line_center_y": 305,
      "font_size": 98,
      "line_spacing_px": 24,
      "letter_spacing_px": 0,
      "character_size_scales": {"5": 1.2},
      "subject_center_x": 830,
      "subject_center_y": 885,
      "subject_scale": 1.0
    },
    "portrait": {
      "title_lines": ["竖版第一行", "竖版第二行"],
      "accent_char_indices": [5, 6, 7],
      "text_center_x": 621,
      "first_line_center_y": 300,
      "font_size": 92,
      "line_spacing_px": 24,
      "letter_spacing_px": 0,
      "character_size_scales": {},
      "subject_center_x": 621,
      "subject_center_y": 1135,
      "subject_scale": 1.0
    }
  },
  "approved_scene_ids": ["01", "02", "03"]
}
```

`approved_scene_ids` 必须覆盖全部场景。用户只确认某一张时，不能自动补全其他场景。

审核页选择正文 BGM：页面展示曲库中的 A/B 等选项和短试听，但 `approval.json.selected_bgm_id` 只保存稳定编号。最终混音读取该编号并使用对应完整原始音频，试听片段不得进入成片。审核页选择是否保留片头，并把布尔值写入 `approval.json.include_intro`；旧审批缺少该字段时兼容为 `true`。保留片头时，片头声音不受 BGM 选择影响：前118帧使用原版 A 音源，选择 A 时原曲从第0秒连续播放，选择 B 或后续选项时仅在第118帧切换正文音乐。不要片头时，画面字幕和场景整体前移118帧，朗读裁掉同长前导静音，所选 BGM 直接从 `body_start_seconds` 起播，使正文画面、人声与所选 BGM 从0秒同步开始。新增或替换曲库音频时，先检测开头静音并把首个有效声音位置写入 `body_start_seconds`；最终混音必须从该位置读取，使正文开始与 BGM 起声严格同步，而不是继续等待音频文件自带的空白。

选项 B 永久固定为“溯溪”，完整音源是 `assets/bgm/option-b-suxi.mp3`，正文起播点固定为 `0.225147` 秒。曲库健康检查必须同时锁定文件名、文件哈希、试听文件哈希、立体声属性和起播点；不得用试听片段、重编码版本或其他同名文件替换正式音源。

声音比例使用用户提供的参考混音校准：朗读增益 `+2 dB`，片头 BGM 保持 `0 dB`，正文 BGM 使用 `+7.1 dB`。同源 BGM 侧声道拟合相关度为0.999991；参考中人声高于背景音乐约4.08 dB。最终混音只提高正文 BGM，不得连带放大片头，也不得通过自动闪避改变句间比例。把单声道朗读等量复制到左右声道中央，保留 BGM 原始左右声道信息，输出48kHz、192kbps双声道AAC；不得再让 `amix` 继承朗读的单声道布局而压扁音乐。测量记录保存在 `assets/bgm/mix-ratio-calibration.json`。

固定品牌栏不进入审核页或审批数据；这里固定的是头像与版式，正文左上角文字仍读取 `plan.title` 中的红色本期主标题，其字号与右上角品牌语一致。审核页只允许改变：

- 正文背景音乐选项；
- 是否保留片头；
- 片头标题文字与分行，保持一至三个非空行；
- 横版与竖版封面的文案和分行；
- 两张封面的强调色字符；
- 两张封面的文字位置、整体字号、行距、字距、选中字符的独立字号、主体图位置和等比缩放。

审核页中两张封面必须同时出现。文字直接在画布内编辑，移动和整体缩放通过画布内拖拽完成，不使用右栏滑杆。文字框使用三向控制：右下角只以拖动开始时的文字框视觉中心为锚点等比缩放整体排版，字号、既有行距和既有字距按相同比例变化，不得让文字框发生可见平移；底边中点只上下拖动调整行距；右边中点只左右拖动调整字距，调整时固定文字框左边，控制点随鼠标连续移动并限制在画布内，避免文字甩出画布后无法继续操作。三个控制点必须在每一次指针移动时刷新实际逐字字号、行高和字距，即使文字编辑框仍处于激活状态也不得延迟到失焦或点击空白处后生效。横版与竖版共享背景色和主体素材，但使用独立坐标。封面文字拖选完成后必须保存字符范围，并用页面自己的选中底色持续显示；鼠标从文字移动到按钮时不得清除选区，按钮也不得在按下时重新抓取并覆盖已保存范围。强调色和单字字号操作必须立即刷新画布，只在至少一个字符实际变化时显示成功；选区为空或状态未变化时给出对应提示。点击画布空白处或其他非编辑区域时，取消当前图层和文字选区，只隐藏边框、控制点与高亮，不撤销已保存排版。行距与字距按封面分别保存。复制确认数据后要显示明确的成功或失败状态。

用户可自然语言反馈：

```text
图07：人物距离更近，删除右侧问号
图12：通过
其余全部通过
```

将反馈转成计划修改时，保留未被点名的已通过图片。

## 配图参考

不要一次传入全部参考图。每张图只选择：

- 一至两张原始语义参考；
- 一张用户认可样本；
- 一张底图颜色参考。

参考图承担不同角色时，在提示词中按顺序说明。图片生成完成后必须回到同一审核页，不要在多个窗口分散确认。

## 配图调度：消除批次空转

发图前先准备全部提示词、参考图和依赖关系。任务包完成后立即发出首批最多3张就绪任务，正常无外部阻塞时目标在10秒内开始请求。最多保持3张图片在途；任一张返回后，先做最小计时和路径记录，再立即补发下一张已就绪任务，之后才审核、归档、归一化或写进度报告。不得等待一批图片全部结束后再启动下一批，也不得让面向用户的汇报暂停生成循环。

角色连续图只阻塞真正依赖角色锚点的任务，不阻塞其他独立场景。若后端实际排队，仍保持滚动补位并如实报告；不得通过更换低级模型、降低分辨率、缩短提示词、减少参考图或跳过审核换取表面速度。

新任务补位后立即处理刚完成的图片：以原生输出路径为输入，直接运行 `normalize_background.py` 写入最终项目图片，避免中间复制；随后完成必要单图初审。复制、背景归一化和单图初审应与其他远程生成任务重叠。只要生成槽位已补满，这些本地处理不会降低图片并发，也不得留到最后集中执行。正常生产最多生成一张最终联系表；只有诊断背景或画风问题时才生成原始图联系表。

每张图片必须记录排队、开始、完成、项目就绪时间和完整耗时；整组必须记录任务包至首个请求、首个请求至最后结果、最后结果至审核页、审核页生成调用、存在就绪任务时的可避免空转、依赖阻塞和最大在途数。不得把重叠请求耗时之和当作真实总耗时；没有同条件串行 A/B 时，不宣称确定加速倍数。

## 审核页优先交付

最后一张项目图片就绪后，只完成不可省略的整组语义、画风、可读文字和文件完整性审核，然后立即生成审核页。审核页文件生成后先向用户发送链接，让用户开始检查；详细 Markdown 耗时报告、诊断文件归档、历史项目检查和与本期审核无关的说明随后进行。详细耗时报告不得阻塞审核页。

审核页生成时间只统计 `generate_review.py` 命令本身；不得把图片复制、归一化、审核、报告写作或代理执行间隔记成“审核页生成”。同时记录 `last_result_to_review_page_seconds`，以便发现图片完成后的流程空档，而不是把空档隐藏在图片模型耗时里。

## 配图审核：平面为原则

默认生成必须坚持二维平面简笔画，先检查整组是否保持同一套扁平人物、纯色块和简洁关系构图，再判断单张是否好看、关系是否清楚、是否真正表达文案。不得在默认提示词中主动邀请渐变、材质、光影、透视或3D效果。

意外生成的渐变、透明、轻微透视或立体结构，只有局限在少量局部、整张图仍明显扁平、与整组一致并确实增强表达时，才作为局部例外保留。例如平面屏障上的局部渐变、平面清单边缘的轻微卷曲、保持平面画风的拼图或路径隐喻都可以成立。若体积光影、写实材质、3D物体或纵深场景主导整张图，或同类表现反复出现并形成整组风格漂移，必须在进入审核页前修正。其余拿不准的局部例外交给用户决定。

## 固定审核页回归

`tests/fixtures/review-schema2/` 是独立测试项目，不属于任何正式文章。审核页生成器或交互逻辑改变后，必须用它重新生成临时审核页，并运行 `scripts/test_review_interactions.cjs`。

自动回归必须实际覆盖：文案与换行、强调色、单字字号、文字移动、行距实时拖动、字距实时拖动且固定左边、右下角围绕视觉中心等比缩放、主体移动、点击空白取消选择、复制成功反馈，以及横竖双封面独立写入 schema 2。测试同时捕获页面脚本错误和控制台警告。

`scripts/check_skill.py` 默认执行完整交互回归。`--skip-review-browser` 只用于诊断浏览器运行环境，必须产生提醒；带提醒的体检不代表 Skill 已固定。不得再以功能代码存在、页面脚本语法正确或人工试过一次代替自动交互回归。

## 审核后的长任务

完整画面轨通常需要超过60秒。运行 `render_video.py` 时使用可持续等待的执行单元或足够长的超时，期间可以读取进度并向用户更新，但不得因为60秒工具等待上限中止正常进程。只有进程明确失败、输出不可读取或经检查确认长期无进展时才重新渲染。
